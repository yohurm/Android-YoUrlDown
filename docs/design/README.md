## 三句话摘要

1. **能力是完整的**：12 个解析通道、媒体判据、下载与校验、证据链都在，且 8/12 平台有真机闭环证据。
2. **问题是结构**：旧实现单模块平铺 19 个包、公开面过宽、Android（WebView / MediaMuxer）渗进核心，
   导致核心无法在纯 JVM 上测、边界只能靠自觉。
3. **新架构的关键动作**：把 Android 专属能力（JS 求值、页面嗅探、DASH 合并、可播放校验）**外置为 `spi` 实现**，
   核心变成纯 JVM 可测；再把分层写成**可执行的构建校验任务**，让越界直接构建失败。

## 已确认的 6 个决策（按推荐执行）

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D1 | 是否引入 OkHttp | **不引入**，HTTP 用手写 `java.net` 实现 |
| D2 | 是否保留 Rhino | **不保留**，只用 WebView 求值器（由 `app` 注入） |
| D3 | 下载是否要后台/续传 | 前台为主；续传由合入的 `lib_download` 自带 |
| D4 | `sniff` 判据是否公开 | **不公开**，保持 `@RestrictTo` 内部 |
| D5 | AAR 是否对外发布 | **只自用**，不对 `api`/`spi` 做语义化版本承诺 |
| D6 | 平台范围 | **锁定 12 个**，新增平台走 `ParseProvider` 扩展 |
