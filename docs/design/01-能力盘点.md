### 2.3 支撑判据（决定"哪些 URL 才算媒体"）

- `MediaExtensions`：扩展名白名单（含 `bin`，排除 `~tplv-noop.image` 这类伪扩展）
- `ContentTypeProbe`：HEAD + 1 字节 Range 探测，独立于普通 GET
- `MediaUrlSniffer`：30 项黑名单 + UA + 错误码判定
- `BlockPageDetector`：站点拦截/错误页识别（防"错误页被当成作品"的假通过）
- `GalleryImagePolicy` / `ImageUrlTransforms`：图集模式与图片 URL 变换
- `PageUserAgents`：按域名选择 UA（移动/桌面）

## 6. 盘点结论（对架构的直接影响）

1. **能力是完整的**：门面、契约、12 通道、判据、下载、校验、证据链齐备。
2. **但代码是"单模块平铺"**：`lib/` 一个模块 19 个包，provider 与 rules 混放，包名 `com.dlparse.*`
   与新仓库 `com.yohu.*` 不一致。
3. **Android 依赖渗进了核心**：`engine.js`（WebView）、`download.DashMuxer`（`MediaExtractor`/`MediaMuxer`）
   让核心无法在纯 JVM 单测里跑，是迁移时最大的结构性障碍。
4. **没有可执行的边界约束**：只能靠人自觉；参考工程有 `check*` 校验任务，本工程设计里应补上。
