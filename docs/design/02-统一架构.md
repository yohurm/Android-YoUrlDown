# 统一架构设计

> 阶段：**设计**。本文件不涉及任何代码改动；它是后续迁移与实现的唯一依据。
> 约束基线：构建配置与 `GGEC-Android-EarBuds` 对齐（AGP 9.4.1 / Gradle 9.6.0 / Java 21 / compileSdk 37.2）。

## 1. 设计目标

| 编号 | 目标 | 可验证的判据 |
| --- | --- | --- |
| G1 | **核心可在纯 JVM 上测** | 引擎核心单测不启动 Android、不依赖 Robolectric；`./gradlew :lib_urlparse:test` 可跑 |
| G2 | **依赖方向单向** | 有可执行的边界校验任务，越界即构建失败 |
| G3 | **通道可插拔** | 新增平台 = 新增一个 provider + 规则，不改引擎 |
| G4 | **不内置私有服务/凭据** | 仓库内无任何第三方密钥；需要凭据的通道由调用方注入 |
| G5 | **失败可解释** | 每个失败都有稳定的错误码 + 人话解释 + 尝试链 |
| G6 | **证据可复现** | 解析尝试链（哪个通道、为什么失败）作为结构化数据可导出 |

## 2. 分层与依赖方向

```
            ┌──────────────────────────────┐
            │            app               │  界面 / Android 适配 / 装配
            └───────┬──────────────┬───────┘
                    │              │
       （依赖 api 与 spi）   （实现 spi 的 Android 侧适配器）
                    ▼              ▼
            ┌──────────────────────────────┐
            │        lib_urlparse          │
            │  ┌────────────────────────┐  │
            │  │ api   对外唯一公开面    │  │
            │  ├────────────────────────┤  │
            │  │ spi   扩展点契约        │  │
            │  ├────────────────────────┤  │
            │  │ core  引擎编排(internal)│  │
            │  ├────────────────────────┤  │
            │  │ provider / rules / sniff│  │
            │  ├────────────────────────┤  │
            │  │ fetch / util            │  │
            │  └────────────────────────┘  │
            └──────────────────────────────┘
```

**依赖规则（必须由构建任务强制）：**

1. `api` 只能依赖 `api` 自身与 `spi`；**不得**依赖 `core/provider/fetch/sniff/rules` 的具体实现类。
2. `provider` 只能通过 `spi` + `fetch` + `sniff` + `rules` + `util` 交互；**不得**依赖 `app`、`android.webkit.*`、`android.media.*`。
3. `rules` 是**纯函数层**：只做字符串/JSON 处理，不得做 IO、不得依赖 Android、不得依赖 `fetch`。
4. `lib_urlparse` 不做下载：只交出媒体地址与请求头，下载、合并、落盘都在 `app`（见 §9）。
5. `lib_urlparse` 整体**不得**出现 `android.webkit` / `android.media` / `android.content.Context`；
   这些能力一律通过 `spi` 由外部注入。

## 3. 模块划分

| 模块 | 类型 | 职责 | 关键约束 |
| --- | --- | --- | --- |
| `lib_urlparse` | `com.android.library` | 解析引擎：契约、编排、通道、规则、判据 | 不出现 WebView / Media* / Context |
| `app` | `com.android.application` | 界面、Android 适配器（WebView 求值/嗅探）、下载子系统（调度、HLS、DASH 合并、落盘）、装配 | 只通过 `api`/`spi` 使用引擎 |
| `lib_download` | `com.android.library` | 通用直链下载引擎：分块、SQLite 断点、重试（合入自 `lib_common`，见 05） | 不认识解析结果；由 `app/download/AssetDownloader` 桥接 |

**为什么引擎仍是 Android library 而不是纯 Java library**：需要 `androidx.annotation` 与 AAR 分发形态，
且将来可能有少量 Android 常量；但**不引入 Android API 依赖**，靠边界任务守住。

**Android 专属能力的三处外置（这是与旧实现最大的结构差异）：**

| 旧位置 | 新位置 | 原因 |
| --- | --- | --- |
| `engine.js.WebViewJsEvaluator` / `WebViewPageSniffer` | `app` 的适配器，实现 `spi.JsEvaluator` / `spi.PageSniffer` | 让核心可 JVM 测 |
| `download.DashMuxer`（`MediaExtractor`/`MediaMuxer`） | `app/download/DashMuxer`，由下载流水线直接调用 | 合并属于下载，不属于解析；`spi.MediaMuxer` 已删 |
| `util.MediaVerifier`（可播放校验） | `app`（或 `spi.PlayabilityVerifier` 实现） | 依赖系统媒体框架 |

## 4. 关键契约（签名级草案）

> 以下为设计草案，命名可在实现时微调；**语义不可弱化**。

### 4.1 对外 API（`api` 包）

```java
public final class UrlParseEngine {
    public static Builder builder();
    public UrlParseResult parse(UrlParseRequest request) throws ParseFailure;
    public ParseTrace lastTrace();           // 结构化尝试链（G6）
}

public final class UrlParseRequest {
    public static Builder builder(String rawInput);
    public Builder platformHint(Platform p);
    public Builder timeoutMs(long ms);
    public Builder parseOnly(boolean v);     // 只解析（下载由 app 承担）
}

public final class UrlParseResult {
    public Platform platform();
    public String channel();
    public String workId();
    public String title();
    public Author author();
    public List<MediaAsset> assets();        // 统一的媒体条目
    public Map<String, String> extras();
    public ParseTrace trace();
}

public final class MediaAsset {
    public Kind kind();                      // VIDEO / IMAGE / AUDIO / COVER
    public String url();
    public String mimeType();
    public long sizeBytes();                 // 未知为 -1
    public Map<String, String> headers();    // 下载时需要的头（Referer/UA）
}
```

### 4.2 扩展点（`spi` 包）

```java
public interface ParseProvider {
    String channel();
    boolean canHandle(ParseContext ctx, ParseRequestView req);
    ParseOutcome parse(ParseContext ctx, ParseRequestView req) throws ParseFailure;
}

public interface ParseContext {
    HttpClient http();
    EngineLogger logger();
    String resolvedUrl();
    <T> T service(Class<T> type);            // JsEvaluator / PageSniffer ...
    ProviderConfig config();                  // 超时、UA 覆盖、调用方凭据引用
}
```

### 4.3 注入服务（由 app 或调用方实现）

```java
public interface JsEvaluator {             // 线程约束写进 javadoc 并做运行时校验
    String loadAndEvaluate(String pageUrl, String script, long timeoutMs) throws Exception;
    String evaluate(String script, long timeoutMs) throws Exception;
    void release();
}

public interface PageSniffer {             // 页面媒体嗅探
    SniffResult sniff(String pageUrl, long timeoutMs, SniffOptions options) throws Exception;
    void release();
}

public interface CredentialProvider {      // 调用方凭据；默认实现返回"未配置"
    Optional<String> endpoint(String channel);
    Optional<String> apiKey(String channel);
}
```

## 5. 通道调度模型（比现状显式化）

现状是"注册顺序 + `canHandle` + 兜底 sniffer"，隐式且易错（曾出现专用通道被通用通道抢走）。
设计改为**显式调度表**：

1. **收集候选**：`platformHint` 优先；否则按 host 匹配注册表。
2. **排序**：`Priority` 枚举（`DEDICATED_WEB > DEDICATED_API > CLOUD > SNIFFER`），同优先级按注册顺序。
3. **逐个尝试**：每个通道的失败都必须记录到 `ParseTrace`（channel、reason、耗时、是否可重试）。
4. **可重试语义**：`NETWORK` / `UNEXPECTED_RESPONSE` 允许换下一个通道；
   `CREDENTIALS_MISSING` / `CHANNEL_DISABLED` 只记录不重试（配置问题，换通道无用）。
5. **兜底**：`SNIFFER` 永远最后；其结果若被 `BlockPageDetector` 判为拦截页，则**整体失败**而非返回假结果。

## 6. 线程与生命周期

- `lib_urlparse` **不创建任何线程**；所有方法在调用方线程执行（可预期、可测）。
- 需要并发时由调用方自己开线程；下载的并发由 `app` 的 `DownloadRunner` 管。
- `JsEvaluator` / `PageSniffer` 有线程亲和性（需 Looper），**契约里写明要求，并在 `ParseContext` 注入时一次性校验**。
- `release()` 的归属：谁创建谁释放。引擎不替你释放注入的服务。

## 7. 错误模型

```java
public enum FailureReason {
    UNRECOGNISED_INPUT,   // 没有通道认领
    NO_MEDIA_FOUND,       // 认领了但没解析出媒体
    UNEXPECTED_RESPONSE,  // 结构不符 / 页面改版
    NETWORK,              // 网络或 JS 求值失败
    CREDENTIALS_MISSING,  // 需要调用方配置
    CHANNEL_DISABLED,     // 缺少注入服务
    CANCELLED,
    INTERNAL
}
```

- `ParseFailure` 携带：reason、channel、message、`retryable()`、`userHint()`（下一步该做什么）、cause。
- **禁止**用 `null`/空列表表示失败；**禁止**把拦截页包成成功结果。

## 8. 凭据与合规（硬约束）

- 仓库内**不得**出现任何第三方服务的密钥、Cookie、私有域名常量。
- 需要凭据的通道一律通过 `CredentialProvider` 注入；未注入时返回 `CREDENTIALS_MISSING` 并给出配置指引。
- 规则/常量文件里出现疑似密钥的字面量时，边界校验任务应报错（关键词扫描：`api_key`、`token=`、`cookie`）。

## 9. 下载子系统设计（`app/download` + `lib_download`）

下载需要 `Context`、SQLite 断点、通知、网络状态与系统媒体框架，放进 `lib_urlparse` 会破坏「核心纯 JVM 可测」，
所以 **`lib_urlparse` 只解析、不下载**：它交出 `UrlParseResult`（媒体地址 + 下载所需请求头），下载由 `app` 完成。

```
app
 ├── task/      DownloadRunner（队列 / 并发 / 暂停继续 / 等网络 / 自动续传）· DownloadService（前台通知）· TaskStore（落盘）
 ├── download/  DownloadPipeline（一次解析结果 → 一组文件）
 │     ├── AssetDownloader  直链 → lib_download（分块 + SQLite 断点）
 │     ├── hls/HlsDownloader M3U8（AES-128 / fMP4 MAP / 字节范围，分片级续传）
 │     ├── DashMuxer         分离音视频 → MediaMuxer 合并
 │     ├── ContainerProbe    容器签名校验（拒绝拦截页）
 │     └── MediaFileNames    命名（真实扩展名白名单）
 └── lib_download  通用下载引擎（合入自 lib_common，见 05）
```

| 关注点 | 设计 |
| --- | --- |
| 协议 | HTTP 直链（分块断点）+ M3U8（含 AES-128）+ 分离流（视频/音频分别下完再合并） |
| 命名 | 平台 id + workId + 标题摘要 + 序号 + 真实扩展名；扩展名必须来自白名单（拒绝 `~tplv-noop.image` 类伪扩展） |
| 去重 | 同 URL 在一次任务内只下一次；同一原链接再次加入时先提醒（见 07） |
| 暂停 / 取消 | `DownloadPipeline.Control` 贯穿所有下载；暂停留断点，取消不留 `.part` |
| 失败 | 统一归到 `DownloadError`（可否重试、是否等网络、是否需重新解析）；不允许"部分成功"被当成整体成功 |
| 校验 | 字节数 + 容器签名；可播放校验用系统框架 |
| 落盘 | 目录由 `app` 决定（应用私有外部目录 `downloads/`） |

流程、状态迁移与自动续传规则见 [07-操作流程.md](07-操作流程.md)。

## 10. 可观测性（G6）

`ParseTrace` 结构：

```java
public final class ParseTrace {
    public List<Attempt> attempts();   // channel, verdict, reason, elapsedMs
    public String resolvedUrl();
    public Map<String, String> facts();// 只放可公开的事实：状态码、长度、命中的规则名
}
```

- 事实（facts）只记录**可公开**内容，不记录响应正文、不记录凭据。
- 日志分级：`ERROR/WARN/INFO/DEBUG`，默认 `INFO`；正文级内容只在 `DEBUG` 且显式开启时输出。

## 11. 构建期边界校验（把设计变成可执行约束）

在 `lib_urlparse/build.gradle` 里新增任务（思路对齐参考工程的 `check*` 任务）：

| 任务 | 断言 |
| --- | --- |
| `checkNoAndroidFrameworkImports` | `src/main/java` 中不得出现 `import android.webkit.` / `android.media.` / `android.content.Context` |
| `checkLayerBoundary` | `api`/`spi` 不得 import `provider/fetch/sniff/rules`；`rules` 不得 import `java.io/nio/net`、`fetch`、`android.*` |
| `checkNoSecrets` | 不得出现疑似密钥字面量（`api_key`、`secret`、`token=`、`sessionid`） |
| `checkPublicApiJavadoc` | `api`/`spi` 的公开类型必须有 javadoc（可放宽为警告，先做统计） |

这些任务挂到 `check` 上，让"架构"不是文档里的约定，而是构建失败条件。
